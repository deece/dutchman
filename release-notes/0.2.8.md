Dutchman Convert 0.2.8 keeps more of a design's history and says more plainly what it kept. Fusion extrudes use the sketch region their end face proves, where it can be proven, more Fusion and Inventor features are rebuilt, and a feature SolidCraft refuses is reported as SolidCraft's, with a link. On the Voron V1.8, 253 of the 1,102 features that need rebuilding are rebuilt, sketches included; 0.2.7 counted 290, but 0.2.8 no longer counts features it can't confirm, such as ones that only re-apply to a body that already holds them. A conversion now measures memory rather than guessing it, so files that used to be refused convert, and on Windows it no longer opens a terminal window for each SolidCraft check.

## What's new

- **Right shapes, or none.** A shape Dutchman can't prove is refused or marked, not kept wrong. Fusion extrudes take the profile their end face proves instead of a guess, a kept extrude's swept region is compared with the source's where it can be and marked unverified where it can't, and a region using part of a crossed circle is selected by a point inside it. A partial history is checked against the bodies Fusion stores where it stops: when the rebuilt features give fewer bodies, or one in another place, the report has `history/body-mismatch` and the result card says so, and that the final shape is still correct. A profile that is a whole sketch with several regions is kept only when SolidCraft confirms it, a through cut no longer takes its far face as its profile, and a Fusion Base Feature whose body a later move or blend changes is no longer rebuilt with those changes applied twice (joins and cuts after it are kept but counted as re-applied, not rebuilt). Older versions could replay such features as a wrong solid, with no error: in our test library, 1 of 185 comparable files was affected; files whose kept features changed couldn't be compared.
- **More history kept.** Extrudes that start or end at a face of an earlier state, end at a face's plane, or start at a plane keep their history. So do holes placed at several sketch points, counterbores and countersinks with a drill point (SolidCraft 0.22.1 and newer), fillets with several radius groups, bodies a file leaves unnamed (as Inventor parts do), Move Face along a face's normal, Fusion cylinder and cone primitives (cones on SolidCraft 0.24.1 and newer), and Inventor sheet-metal plates attached at 90 degrees, which become edge flanges. A Fusion Canvas (a reference image) no longer stops a history.
- **Clear reasons, named parts.** A feature SolidCraft won't rebuild is reported as "SolidCraft refused …", with a category and the upstream issue where one exists, such as a fillet wider than the face beside it. Messages name the selection form they can't handle, and anonymous reports list blocked features by timeline position and form. The report and the result card also name parts whose position nothing confirms: a warning for parts at their design's origin because their placement could not be read, and a note for parts resting on a stored pose alone.
- **Memory measured, not guessed.** An estimate from a file's size no longer refuses a conversion or leaves out history, and the desktop's memory warning is gone. A conversion stops with a clear message only when the computer really gets low: under 1 GB free while it holds at least 1 GB. The SolidCraft check stops earlier and the built design is kept, marked unverified with the reason. In a batch, a file stopped alongside others converts again on its own at the end. `convert-all` and `watch` no longer stop a file at 8 GB by default. Reference sketches no longer copy the whole model for each group of components, which lowers the Voron V1.8's peak by about 2 GB with the same output.
- **No terminal windows on Windows.** Converting in the desktop app no longer opens a terminal window for each SolidCraft check. Each file also converts in its own process, so a crash ends that file and not the app.
- **Cards that fit, and report from them.** Result cards fit the window: a failed file's help folds under **Help us fix it**, and **Ask your AI about this file** shows a short prompt in a small box. Any result with a loss has **Report this file…**.
- **Finding SolidCraft, updates and the command line.** The desktop app and the command line look for SolidCraft the same way, including per-user installs. When it isn't found, the app and reports say where they looked. `SOLIDCRAFT_CLI` is documented. **Update** asks for the newest release each time it's pressed and shows its notes properly formatted. `convert` writes `--report-anon` too, `convert-all` warns when an argument looks like an output folder, progress shows only in a terminal, and `--write-replay` writes the replay script next to the design.

## Known issues

- A feature can still replay from the wrong sketch region and count as rebuilt when Dutchman can't check it against the source; the result card says how many such extrudes a file has, and the JSON report marks each one unverified. A check for every case waits on the decoder (Dutchman, #489; cadmpeg #944).
- A large Fusion multi-document archive can still need about 18 GB with the SolidCraft check, down from about 22 GB (Dutchman, #227).
- A part with no joint or stored pose can land away from where the source shows it. These parts are named in the report and on the result card (Dutchman, #512).
- A Fusion Remove whose bodies the decoder doesn't resolve can still keep the removed body in the converted design (Dutchman, #485).
- An extrude that ends at a work plane or point after earlier features is still kept as geometry (Dutchman, #486).
- An extrude that ends at a face with holes or curved edges is kept as geometry.
- SolidWorks mates are not converted, and most of a large SolidWorks assembly converts as geometry (cadmpeg, #487).
- The estimate before a conversion can be far from the real peak in either direction, since it comes from the file's size. It no longer decides anything (Dutchman, #388).
- Several large files converting at once in the desktop can skip SolidCraft checks to fit, and a file stopped for memory converts again alone at the end. A file that can't fit takes minutes to stop rather than being refused at once.
- macOS compresses and swaps rather than running out, so a large design can use far more than the Mac's memory and convert slowly.
