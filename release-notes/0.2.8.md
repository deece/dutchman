Dutchman Convert 0.2.8 keeps more of a design's history and says more plainly what it kept. Fusion extrudes use the sketch region their end face proves, where it can be proven, more Fusion and Inventor features are rebuilt, and a feature SolidCraft refuses is reported as SolidCraft's, with a link. On the Voron V1.8, 299 of the 1,109 features that need rebuilding are rebuilt, up from 290, sketches included. A conversion now measures memory rather than guessing it, so files that used to be refused convert, and on Windows it no longer opens a terminal window for each SolidCraft check.

## What's new

- **Right profiles, checked where they can be.** Fusion extrudes are read with the profile their end face proves, where it can be proven, instead of a guess that could pick the wrong region. Dutchman also compares a kept extrude's swept region with the source's end face where it can, and marks the extrude unverified where it can't. A region using part of a circle crossed by another is selected by a point inside it, taken from its stored boundary. Older versions could replay such an extrude as a wrong solid, with no error: in our test library, 1 of 185 comparable files was affected; files whose kept features changed couldn't be compared.
- **More history kept.** Extrudes that start or end at a face of an earlier state, end at a face's plane, or start at a plane keep their history. So do holes placed at several sketch points, counterbores and countersinks with a drill point (SolidCraft 0.22.1 and newer), fillets with several radius groups, bodies a file leaves unnamed (as Inventor parts do), Move Face along a face's normal, and Inventor sheet-metal plates attached at 90 degrees, which become edge flanges.
- **Clear reasons, named parts.** A feature SolidCraft won't rebuild is reported as "SolidCraft refused …", with a category and the upstream issue where one exists, such as a fillet wider than the face beside it. Messages name the selection form they can't handle, and anonymous reports list blocked features by timeline position and form. The report and the result card also name parts whose position nothing confirms: a warning for parts at their design's origin because their placement could not be read, and a note for parts resting on a stored pose alone.
- **Memory measured, not guessed.** An estimate from a file's size no longer refuses a conversion or leaves out history, and the desktop's memory warning is gone. A conversion stops with a clear message only when the computer really gets low: under 1 GB free while it holds at least 1 GB. The SolidCraft check stops earlier and the built design is kept, marked unverified with the reason. In a batch, a file stopped alongside others converts again on its own at the end. `convert-all` and `watch` no longer stop a file at 8 GB by default. Reference sketches no longer copy the whole model for each group of components, which lowers the Voron V1.8's peak by about 2 GB with the same output.
- **No terminal windows on Windows.** Converting in the desktop app no longer opens a terminal window for each SolidCraft check. Each file also converts in its own process, so a crash ends that file and not the app.
- **Cards that fit, and report from them.** Result cards fit the window: a failed file's help folds under **Help us fix it**, and **Ask your AI about this file** shows a short prompt in a small box. Any result with a loss has **Report this file…**.
- **Finding SolidCraft, updates and the command line.** The desktop app and the command line look for SolidCraft the same way, including per-user installs. When it isn't found, the app and reports say where they looked. `SOLIDCRAFT_CLI` is documented. **Update** asks for the newest release each time it's pressed and shows its notes properly formatted. `convert` writes `--report-anon` too, `convert-all` warns when an argument looks like an output folder, progress shows only in a terminal, and `--write-replay` writes the replay script next to the design.

Same machine, same settings, one conversion at a time, 0.2.7 and 0.2.8 run back to back:

| Voron V1.8 | 1,220 of 1,222 | 290 of 1,348 | 299 of 1,109 | 7:13 | 7:24 | 11.8 GB | 11.8 GB |
| RailCore II 300ZL | 379 of 379 | 153 of 440 | 153 of 440 | 1:36 | 1:38 | 3.9 GB | 3.6 GB |
| RailCore II 300ZLT | 396 of 396 | 124 of 371 | 124 of 371 | 1:57 | 1:49 | 3.8 GB | 3.4 GB |

Features rebuilt counts sketches and imported bodies as well as modelling features, out of the features that need rebuilding. Of the V1.8's, 91 are in parts whose whole history matched the source's shape; the rest of a partial history replays without error, with no source shape to compare it to.

Earlier releases counted component inserts and other features that needed no rebuild as kept; counts here are features actually rebuilt, so they can look lower.

## Known issues

- A feature can still replay from the wrong sketch region and count as rebuilt when Dutchman can't check it against the source; such extrudes are marked unverified in the JSON report. A check for every case waits on the decoder (Dutchman, #489; cadmpeg #944).
- A Fusion extrude using several regions of a crossed sketch can keep a wrong intermediate shape in a partial history. The result card doesn't warn of it; the JSON report marks the extrude `profile_unverified`. In our test library this is 1 of 185 comparable files, and it's new in 0.2.8.
- A large Fusion multi-document archive can still need about 18 GB, more with the SolidCraft check (Dutchman, #227).
- A part with no joint or stored pose can land away from where the source shows it. These parts are named in the report and on the result card (Dutchman, #512).
- A Fusion design with Remove features can keep the removed bodies (Dutchman, #485).
- An extrude that ends at a work plane or point after earlier features is still kept as geometry (Dutchman, #486).
- An extrude that ends at a face with holes or curved edges is kept as geometry.
- SolidWorks mates are not converted, and most of a large SolidWorks assembly converts as geometry (cadmpeg, #487).
- The estimate before a conversion can be far from the real peak in either direction, since it comes from the file's size. It no longer decides anything (Dutchman, #388).
- Several large files converting at once in the desktop can skip SolidCraft checks to fit, and a file stopped for memory converts again alone at the end. A file that can't fit takes minutes to stop rather than being refused at once.
- macOS compresses and swaps rather than running out, so a large design can use far more than the Mac's memory and convert slowly.
